# Vision

## The lie

Most “AI can make you a game” systems produce a fragile demonstration:

- inconsistent art,
- code that works once,
- mechanics written from scratch instead of assembled from tested parts,
- no durable asset provenance,
- no reliable editing path,
- and no graceful survival after the generating service or original developer disappears.

They ask generative models to perform precision repetition—the work those models are most expensive and unreliable at.

## The replacement

Playable Lie turns generation into one stage of a larger production system.

The user supplies an idea, concept image, or rough description. The builder chooses legal assets and known-working game modules, then uses AI only where novelty is useful. For character art, AI stuffs the concept into an existing animation mould badly once. A local pipeline creates many nearby mathematical variants, aligns them, rejects failures, and presses the stable features into a coherent result.

The finished output is not a hosted trick. It is an editable project with manifests, source assets, licenses, run reports, and reusable modules.

## What people thought they were getting

- A game worth playing.
- Assets and characters they can keep.
- A world that can be edited, migrated, or inherited.
- Enough automation to make creation accessible without pretending one prompt replaces production.
- A system whose useful parts survive the death of one company or service.

## Product sentence

> Describe the game. Receive a playable, editable project assembled from legal assets, tested components, one-shot generative proposals, and local deterministic repair.
